# 大规模 VLSI 掩模优化：从光刻仿真到全芯片部署

> **论文：** *Large-Scale VLSI Mask Optimization: A Survey*<br />
> **作者：** Ziyang Yu、Bei Yu，香港中文大学<br />
> **类型：** 综述论文，正文 9 页，参考文献 3 页<br />
> **代码与关联阅读：** [OpenILT](https://github.com/OpenOPC/OpenILT) · [CAMO](https://arxiv.org/abs/2404.00980)

这篇论文不是某一种 OPC、ILT 或强化学习算法的完整技术论文，而是一张**大规模计算光刻的领域地图**。它试图回答的问题是：在特征尺寸不断缩小、版图规模不断增大的情况下，怎样把掩模优化从局部热点实验推进到速度可接受、质量可靠、并且能够处理真实全芯片设计的工程流程。

本文结合我的长期阅读笔记，对原论文的五幅关键图逐一解释。图不是装饰：图 1 讲技术演进，图 2 讲正向仿真，图 3 讲学习式仿真器究竟替代了什么，图 4 讲不同优化方法位于哪一层，图 5 讲全芯片部署如何处理规模、重复图形和边界连续性。

文中使用四类标记：**【原文】**表示综述明确陈述的内容；**【理解】**表示为阅读而整理的解释；**【待验证】**表示需要回到原始论文或代码确认；**【研究延伸】**表示不是综述直接验证的研究问题。不要把综述中对被引论文的概括，当成在同一 benchmark 上重新完成的统一实验。

## 0. 五分钟速览：这篇综述的主线

### 0.1 一句话总结

**大规模掩模优化的核心不是单独发明一个更强的优化器，而是同时解决三件相互耦合的事：光刻仿真要足够快，掩模搜索要足够好，全芯片系统要能够承受真实版图的规模与制造约束。**

$$
\text{Fast simulation}
\rightarrow\text{Better mask optimization}
\rightarrow\text{Full-chip integration}.
$$

### 0.2 三层技术地图

| 层次 | 主要问题 | 代表性路线 |
|---|---|---|
| 正向仿真 | 给定 Mask，如何快速预测 wafer pattern？ | Hopkins/SOCS/FFT、GPU、LithoGAN、DAMO、DOINN、Nitho |
| 逆向优化 | 给定 Target，如何生成高质量、可制造的 Mask？ | MOSAIC、GLS-ILT、Multi-level ILT、OpenILT、GAN-OPC、DevelSet、RL-OPC、CAMO |
| 系统部署 | 如何从 clip 走向真实 full chip？ | 重叠分块、D2S、DAMO、AdaOPC 2.0、FuILT |

### 0.3 读完应该留下的四个判断

1. **ILT 是逆问题，不是“直接画一个更漂亮的掩模”。** Mask 经过光学和光刻胶模型后才产生 wafer pattern，因此优化目标必须通过正向仿真定义。
2. **AI 的位置非常重要。** 一个模型可能替代仿真器、预测初始 Mask、指导每轮更新，或者直接做序贯决策；这些不是同一种“AI + ILT”。
3. **局部指标不等于全芯片能力。** 小图块上的 EPE、L2 或 runtime，不能自动推出边界连续性、内存占用和整层吞吐。
4. **综述是检索入口，不是统一排行榜。** 被引用工作的指标、数据集、工艺角和硬件条件通常不同。

## 1. 问题定义：为什么 Mask 不能等于 Target？

### 1.1 从设计图形到晶圆图形

**【原文｜Section 1】** 当 VLSI 特征尺寸小于曝光波长时，衍射、干涉和工艺变化会阻碍设计图形从 Mask 忠实转移到 wafer。掩模优化因此会有意修改图形，并插入 SRAF 来预补偿光刻失真。

**【理解】** 设计工具给出的是“希望晶圆上出现什么”的 Target；曝光设备使用的是“应该拿什么形状去曝光”的 Mask。二者不相同，往往正是为了让最终 printed pattern 更接近 Target。

```text
Target layout
     │
     ▼
Mask generation / optimization ──► Mask
                                      │
                                      ▼
                            Optical imaging
                                      │
                                      ▼
                         Aerial image / resist model
                                      │
                                      ▼
                              Printed pattern
                                      │
                                      ▼
                         Compare with Target → update
```

关键区别是：**光刻仿真是正向问题，OPC/ILT 是依赖正向仿真的逆向问题。**

### 1.2 OPC、SRAF、MBOPC 和 ILT

| 技术 | 做什么 | 主要取舍 |
|---|---|---|
| Rule-based OPC | 根据线宽、间距、线端等规则修改边缘 | 快且直接，但依赖规则覆盖能力 |
| Model-based OPC | 用光刻模型反复移动多边形边缘 | 物理依据更强，但需要反复仿真 |
| SRAF | 在主图形旁插入通常不希望被印出的辅助特征 | 改变光场以改善主图形成像，同时引入规则约束 |
| Pixel-based ILT | 在高维像素或连续表示中反演掩模 | 搜索空间灵活，但计算和制造复杂度高 |

综述指出，ILT 可能带来更好的图形保真度和更宽的工艺窗口，但全层 ILT 可能需要数千 CPU 核运行数天；自由优化还会生成传统写入设备难以处理的复杂曲线。因此，“仿真误差更小”不等于“工程上更值得采用”。

### 1.3 三个互相耦合的瓶颈

每轮 Mask 更新通常都要调用 lithography simulator，因此存在三层瓶颈：

1. **仿真瓶颈：** 单次 forward 太慢，优化迭代就无法扩展。
2. **搜索瓶颈：** Mask 空间巨大，目标之间相互冲突，收敛可能缓慢或不稳定。
3. **部署瓶颈：** 即使 clip 能优化，完整芯片仍会遇到分区边界、内存、通信和吞吐问题。

这正是论文按“仿真 → 优化 → full chip → open challenges”组织内容的原因。

图 1 的横轴大致表达时间演进，纵向对象仍是完整光刻链路：source、lens、mask、projection lens、wafer。图中最重要的不是年份本身，而是**优化对象和计算方式发生了变化**：

- 从 **No Correction** 开始，Mask 近似等同于设计图形，无法主动补偿成像失真。
- **Rule/model-based OPC** 开始使用规则或光刻模型移动边缘。
- **Assist Features** 不直接承担主图形，而是改变局部光场，帮助主图形获得更稳定的印刷结果。
- **ILT** 把 Mask synthesis 写成成像系统的逆问题，在更自由的表示空间中搜索。
- 最上方的 **Computational Lithography** 不是某一个算法，而是把 forward imaging、simulation、optimization 和 evaluation 组合起来的系统性领域。

**图 1 的核心信息：** 技术演进不是简单的“规则方法被神经网络替代”，而是从人工规则逐步走向模型驱动、逆问题求解和计算系统协同。算法越灵活，通常越依赖仿真、算力和制造约束。

**不要过度解读：** 图 1 是概念演进图，不是每种技术的严格时间线、性能排名或工业采用率统计。

## 3. 图 2：光刻仿真是所有优化的地基

<Figure
  src='/images/large-scale-mask-survey/figure-2-lithography-system.png'
  alt='原论文图 2：光刻成像系统组成以及 Mask 到 Aerial Image 再到 Resist 的仿真流程'
  caption='原论文 Figure 2（PDF 第 3 页）：左侧是照明源、透镜、光瞳、掩模、光刻胶和衬底；右侧是 Mask → optical model → aerial image → resist 的正向流程。'
/>

### 3.1 图 2 左半：设备组成

左半图把物理链路画成 source → condenser/lens → pupil/lens → mask → projection lens → wafer/resist。它提醒我们：光刻不是一个“把二值图片模糊一下”的单一操作，部分相干照明、衍射、光学孔径、掩模效应和光刻胶显影都会影响结果。

### 3.2 图 2 右半：仿真数据流

右半图更适合和 OpenILT 的记号对应：

$$
M \xrightarrow{\text{optical model}} I
\xrightarrow{\text{resist model / threshold}} Z.
$$

- `M` 是待评估的 Mask；
- 光学模型输出 `I`，通常称 aerial image 或 intensity；
- resist model / threshold 把 `I` 转为 printed pattern `Z`；
- `Z` 再与 Target 比较，产生 EPE、L2、PVB、process window 等反馈。

论文提到 Hopkins 表述、多个卷积核和 SOCS/FFT 加速。ICCAD-2013 mask optimization contest 提供的开放仿真器和 benchmark 对学术复现很重要；商业工具如 Calibre 具有校准和流程优势，但封闭性限制了公开复现。

### 3.3 为什么仿真速度决定优化规模？

如果一次 Mask 更新需要一次甚至多次 process-corner simulation，那么优化器再先进也会受到 forward latency 限制。加速路径包括：

- 稀疏表示、区域分解和简化模型；
- FFT 卷积和 GPU 并行；
- 用学习式 surrogate 预测 aerial image 或 printed contour；
- 在速度和物理一致性之间选择合适精度。

**关键判断：** surrogate 不是“只要快就行”。要问它预测的是 aerial image、resist image 还是最终 contour；它在新图形、新图层和新工艺角上是否可靠；误差会不会在后续迭代中被放大。

## 4. 图 3：学习式仿真器到底替代了哪一部分？

<Figure
  src='/images/large-scale-mask-survey/figure-3-surrogate-simulators.png'
  alt='原论文图 3：LithoGAN、DAMO、DOINN 和 Nitho 四种典型学习式光刻仿真框架'
  caption='原论文 Figure 3（PDF 第 4 页）：四种学习式光刻仿真框架。阅读重点不是比较网络名称，而是判断每种方法替代或保留了 forward lithography pipeline 的哪一部分。'
/>

图 3 包含四个子图，它们代表不同的“学习式仿真”插入方式：

### 4.1 LithoGAN：从 Mask 到 printed pattern 的生成映射

(a) LithoGAN 使用 conditional GAN 学习 Mask 到 resist/printed pattern 的映射，并加入中心坐标回归分支。它的直觉是用生成模型直接逼近光刻输出，但综述指出其设定受单个 contact prediction 等应用范围限制。

**应该看懂：** 这是 image-to-image surrogate，不等于完整的 ILT solver。它替代的是 forward prediction；后面是否还要用它做梯度优化，取决于具体系统。

### 4.2 DAMO：面向速度和规模的嵌套 U-Net

(b) DAMO 使用嵌套 U-Net（DLS）并将 Mask pattern 编码到 RGB 通道，目标是快速预测 wafer image。综述把 DAMO 同时放在 surrogate simulation 和 full-chip optimization 中，因为一次快速 forward prediction 能直接降低大规模优化的成本。

**应该看懂：** DAMO 的价值不是“U-Net 这个名字”，而是把输入编码、网络容量和 full-chip partition/optimization 流程组合起来。

### 4.3 DOINN：把长距离光学先验放进 FNO

(c) DOINN 使用 Fourier Neural Operator 表达长距离光学影响，再用浅层 CNN 补充局部边缘细节。光刻图形并非只受局部像素影响；FNO 的频域结构适合表达较长距离的算子关系。

**应该看懂：** 这是把物理结构和网络归纳偏置结合，而不是简单堆叠更深 CNN。仍然需要验证其跨图形和跨工艺泛化。

### 4.4 Nitho：学习光学核，再用 SOCS 重建 aerial image

(d) Nitho 使用 physics-informed coordinate network 回归复数光学核，再通过 SOCS 重建 aerial image。与直接预测 contour 相比，这条路线保留了更明确的物理计算接口，因此更适合作为重复调用的 aerial-image engine。

**四个子图的比较方法：**

| 方法 | 学习对象或主要替代部分 | 物理结构保留程度 |
|---|---|---|
| LithoGAN | Mask → printed/resist mapping | 偏端到端映射 |
| DAMO | 快速 wafer-image prediction | 网络与系统规模协同 |
| DOINN | 长距离光学算子 + 局部细节 | 显式引入 FNO 先验 |
| Nitho | 复数 optical kernels，再经 SOCS | 保留较清晰的物理重建路径 |

**不能从图 3 得出：** Nitho 一定比 DAMO 更准确，或所有 surrogate 都能无缝替代 calibrated commercial simulator。图 3 展示的是框架差异，不是统一实验排名。

## 5. 图 4：从数值 ILT 到 RL，方法究竟改变了什么？

  alt='原论文图 4：MOSAIC、GLS-ILT、Multi-level ILT、GAN-OPC、Neural-ILT 2.0、SRAF 字典学习、DevelSet、RL-OPC 和 CAMO 的方法框架'
  caption='原论文 Figure 4（PDF 第 6 页）：典型掩模优化框架。应沿“表示、更新方式、是否学习、是否序贯决策”读图，而不是把它看成算法排行榜。'
/>

图 4 最容易被误读。它不是把九种方法放在同一条性能曲线上，而是把不同技术范式并列展示。阅读每个子图时，建议问四个问题：

1. Mask 用像素、level set、神经网络输出还是图结构表示？
2. 更新来自梯度、网络前向、启发式模块还是 RL action？
3. lithography simulation 在 loop 内、网络训练中，还是被 surrogate 替代？
4. 目标是否包含 EPE、process window、mask complexity 和可制造性？

### 5.1 传统数值路线

- **MOSAIC：** 像素级掩模调整，关注 nominal fidelity 与 process window，并提供 fast/exact 梯度路线。
- **GLS-ILT：** 用 level set 表示轮廓演化，通过 CUDA/FFT 加速，强调平滑 Mask 与更短 runtime。
- **Multi-level ILT：** 先在粗分辨率上优化，再回到 native resolution 细化，把昂贵的高分辨率计算推迟到后期。
- **RMO-ILT：** 同时处理多个工艺角，以更严格的 multi-objective 方式增强 process robustness。
- **CTM-SRAF：** 从连续传输掩模中提取 SRAF 插入线索，把 pixel-based ILT 和规则约束下的 assist-feature generation 联系起来。

这些方法分别改变了目标函数、Mask 表示、分辨率调度和底层计算。创新不只等于“发明一个新网络”。

### 5.2 OpenILT 的位置

综述将 OpenILT 放在基础设施位置：它把 lithography simulation、initialization、solver 和 evaluation 做成可组合组件，使用 PyTorch 支持 GPU 与学习方法，并复现 MOSAIC、GLS-ILT、multi-level ILT 等路线。

它的价值在于固定或复用基础条件后更容易回答：改进来自初始化、优化器、仿真器，还是评价条件？这也是我上一篇 OpenILT 笔记中强调的“平台问题”。

### 5.3 学习式和混合路线

- **GAN-OPC：** 直接从 Target 生成接近可制造的 Mask，再结合 lithography-aware loss。
- **Printability predictor：** 预测 EPE 或打印结果，指导 segment correction，减少昂贵的迭代。
- **SRAF dictionary learning / GAN-SRAF：** 学习紧凑的 assist-feature 表示或直接生成 SRAF。
- **Neural-ILT 2.0：** 用领域专用、多任务网络预测 ILT 解，把迭代过程部分迁移为 one-shot prediction。
- **DevelSet：** 神经 level set 加 CUDA optimizer，兼顾快速求解、轮廓平滑和 printability。
- **L2O-ILT：** 将传统 ILT 迭代展开成网络层，学习更新规则或高质量初始化。
- **ILILT：** 使用隐式可微光刻层和工艺条件输入，减少对传统 solver-in-the-loop 的依赖。

### 5.4 RL-OPC 与 CAMO：序贯决策进入 OPC

**【原文】** RL-OPC 将 edge movement 作为 action，用 EPE 和 process-window improvement 相关的 reward 训练策略；CAMO 进一步使用 segment graph、GNN、循环模块和 OPC-inspired modulator，根据当前 EPE 调整动作概率。

可以用下表建立阅读框架，但不能把综述没有给出的细节补成原论文公式：

| RL 要素 | 综述能确认什么 | 仍需回原论文确认什么 |
|---|---|---|
| State | 与当前 Mask/校正状态有关 | 具体编码、感受野、工艺条件是否输入 |
| Action | Edge/segment movement | 离散还是连续、一次修改多少 segment、位移约束 |
| Reward | 与 EPE 和 process-window improvement 有关 | 精确公式、归一化、成本惩罚与权重 |
| Transition | Mask 改变后重新评估 | 每步是否完整仿真、终止条件、预算 |
| Policy | 深度强化学习策略 | 算法、采样、训练集与测试集隔离 |

**重要边界：** 综述没有给出 RL-OPC 的精确 reward 公式，所以不能把个人设计的 $r_t$ 写成 RL-OPC 原文结论。A2-ILT 与 RL 放在相邻叙述中，也应先读原始论文再决定是否严格归为标准 RL。

CAMO 的关键启发不是“GNN 必然优于 CNN”，而是相邻 segment 的动作会相互影响，图结构可能更自然地表达这种关联；最终效果仍取决于 action space、simulation budget、数据和评测设置。

## 6. 指标地图：不能只看一个分数

| 指标 | 衡量什么 | 单独使用的局限 |
|---|---|---|
| EPE | Printed edge 相对于 target edge 的位置偏差或违规数 | 受采样、阈值、聚合方式影响 |
| L2 | 图像/区域级整体误差 | 可能掩盖关键边缘位置的问题 |
| PVB | 不同工艺条件下 printed contour 的变化 | 必须明确 corners 和计算口径 |
| Process window | 满足规格的 focus/exposure 条件范围 | 不能等同于单一 nominal 精度 |
| Shot count / mask complexity | 写入或几何复杂度相关成本 | 设备、fracture 和 writer 条件会影响含义 |
| Runtime / throughput | 单次优化耗时和规模化处理能力 | 必须统一硬件、质量目标和计时范围 |

**实践原则：** 不说“方法更好”，而说“在什么图形、什么工艺条件、什么质量指标和什么计算预算下更好”。

### 7.1 为什么不能简单把 clip 拼起来？

完整芯片有数十亿个图形特征，且光学影响具有邻域依赖。简单切块后分别优化，会让相邻 tile 看到不同的上下文，最终在 domain boundary 处出现不连续、stitching error 和额外修复成本。

因此 full-chip MO 同时是：

- **计算问题：** 内存、GPU/CPU 并行、通信和 I/O；
- **物理问题：** optical context、resist effect 和 process corner；
- **连续性问题：** 相邻 tile 的 Mask 和 gradient 是否一致；
- **重复性问题：** 相同或相似 motif 能否复用已有结果；
- **制造问题：** 曲线复杂度、shot、规则和 writer 限制。

### 7.2 五类框架怎样区分？

| 框架 | 图 5 中体现的核心思想 | 主要代价或风险 |
|---|---|---|
| Intel 早期方案 | overlap tile + boundary padding，独立优化后合并 | 仍可能需要边界 repair |
| D2S | GPU/CPU 集群像一个巨大处理器，尽量避免 partition-and-stitch | 系统硬件与工程集成复杂 |
| DAMO | neural surrogate + adaptive partitioning + clustering | 代理模型泛化与上下文保持 |
| AdaOPC 2.0 | 按局部复杂度选择 engine，并复用 pattern library | 需要可靠的模式匹配和 engine selection |
| FuILT | hierarchical partition + server-worker + gradient fusion + boundary healing | 分布式调度和融合逻辑复杂 |

### 7.3 逐图理解

- **Intel：** 先通过重叠和 padding 保留上下文，再合并 tile；优点是容易利用并行，难点是边界结果仍可能不一致。
- **D2S：** 通过专用的 GPU/CPU 组织方式把完整数据视作一个巨大处理任务，论文综述其可在 24 小时内完成 full-chip curvilinear ILT；这是文献报告，不是本文重新测量。
- **DAMO：** 用快速 surrogate 预测 wafer image，再结合 adaptive partition 和 clustering，在速度与上下文之间折中。
- **AdaOPC 2.0：** 观察 via pattern 的复杂度和重复性，按区域选择合适 engine，并从图形库复用已优化结果。
- **FuILT：** 允许分层分区，但在每轮后做 gradient fusion，再用多级 boundary healing 让相邻 tile 收敛到一致解。

**图 5 的核心信息：** full-chip 不是把小图块算法乘以图块数量。系统必须显式处理上下文、边界、通信、重复图形和内存。D2S 代表“尽量避免拆分后拼接”，FuILT 代表“允许拆分但把一致性纳入算法”，AdaOPC 2.0 则利用图形重复性减少重复计算；这些思路可以互补。

## 8. 综述列出的开放问题

### 8.1 多目标之间的冲突

**【原文】** Mask 优化需要同时兼顾 pattern fidelity、computational efficiency、mask complexity 和 manufacturing robustness。更多 SRAF 或曲线细节可能扩大 process window，却增加写入复杂度和时间。

可以用抽象向量表示个人理解：

$$
\min_M\bigl[
E_{\mathrm{fidelity}}(M),
E_{\mathrm{robustness}}(M),
C_{\mathrm{mask}}(M),
C_{\mathrm{compute}}(M)
\bigr].
$$

这不是论文给出的统一精确目标函数，而是提醒我们：实际最优点通常是 Pareto trade-off，不是单一 loss 的最小值。

### 8.2 可制造性应进入优化内部

传统 writer 对复杂 curvilinear Mask 可能需要大量 shots；MBMW 缓解了部分写入时间问题，但不是所有设备和成本约束都消失。若 ILT 完成后才进行 rule repair，修复可能破坏原来的最优性。

因此更可靠的方向是：在搜索过程中直接加入 mask rule、最小线宽/间距、writer 限制和复杂度成本，而不是最后再补救。

### 8.3 学习模型的可信性与泛化

代理模型和学习式 optimizer 可能在新 pattern、新 layer 或新 process condition 上失效，重新训练和校准代价高。综述提出 physics-informed model、model-driven deep learning、可迁移基础模型和 uncertainty quantification 等方向。

**研究判断：** AI for engineering 的目标不能只是在固定 benchmark 上取得低误差，还要在图形、工艺和算力变化下保持可靠。

## 9. 强化学习是否真的适合 OPC？

本节是基于综述的研究延伸，不是论文贡献列表。

### 9.1 先问 RL 解决了什么真实困难

经典 ILT 已经能使用梯度、level set 和 coarse-to-fine 方案；学习式方法还可以预测 Mask 或初始化。因此引入 RL 前，需要明确：

- action 是否本来就是离散、受约束的 edge movement？
- reward 是否包含难以直接求导的 yield 或制造指标？
- 多个 segment 的长期相互影响是否使序贯决策有优势？
- RL policy 是否能迁移到未见过的 pattern 和 process？

如果只是把可微优化器换成“agent”，却没有独特的问题结构和公平的计算预算，方法论证是不完整的。

### 9.2 一个仅用于实验设计的奖励示例

综述只确认 RL-OPC 奖励与 EPE、process-window improvement 有关，没有给出精确公式。若构造自己的基线，可以把前后指标改善写成：

$$
r_t=\alpha(EPE_t-EPE_{t+1})
+\beta(PVB_t-PVB_{t+1})
-\lambda C(a_t).
$$

这里 $C(a_t)$ 是动作复杂度或成本。这个式子只是“误差改善 + 稳健性改善 - 动作成本”的设计示例，不能归属于 RL-OPC 或 CAMO。实际实验还要处理量纲、奖励稀疏性、simulation cost、动作合法性和多目标冲突。

### 9.3 公平对比的最低要求

| 变量 | 必须固定或报告 |
|---|---|
| Baseline | MBOPC、MOSAIC、GLS-ILT 或其他方法及其超参数 |
| Cost | wall-clock、仿真调用数、训练成本还是迭代数 |
| Environment | optical kernels、resist model、process corners、pattern distribution |
| Split | 训练/测试图形是否真正隔离 |
| Metrics | EPE、L2、PVB、mask complexity、runtime 一起报告 |
| Scale | clip、layer 还是 full chip；边界如何处理 |

## 10. 一条可长期使用的阅读路线

### 路线 A：经典 OPC/ILT

**OpenILT → MOSAIC → GLS-ILT → Multi-level ILT → RMO-ILT**

逐篇追问：优化变量是什么？损失是什么？梯度如何得到？是否处理多个工艺角？如何影响 runtime 与 manufacturability？

### 路线 B：AI 进入优化循环

**GAN-OPC → Neural-ILT / Neural-ILT 2.0 → DevelSet → L2O-ILT → ILILT**

区分直接预测、初始化、展开优化、隐式物理层，以及传统迭代被保留还是替代。

### 路线 C：RL + OPC

**RL-OPC → CAMO**，同时核查 **A2-ILT** 的真实训练机制。

重点记录 MDP、reward、action space、simulation budget、跨版图泛化与公平基线。

### 路线 D：full-chip

**Intel → D2S → DAMO / AdaOPC 2.0 → FuILT**

重点是 partition、optical context、stitching、gradient fusion、pattern reuse 和 GPU/CPU pipeline。

## 12. 总结：这篇综述真正想说明什么？

计算光刻的挑战不再只是“怎样让一个图块印得更像”，而是**怎样以可以承担的计算和制造成本，可靠地完成全芯片掩模优化**。因此研究沿三条互补路径发展：

1. 用物理加速、GPU 和学习式 surrogate 降低一次仿真的成本；
2. 用数值 ILT、深度学习、混合求解和 RL 提升 Mask 搜索质量与效率；
3. 用分区、并行、图形复用、gradient fusion 和 boundary healing 把方法扩展到真实 design layer 与 full chip。

**最重要的研究判断：** 一个可信的 RL + OPC 工作不应只宣布“用 agent 替代传统优化”，而要指出传统方法的具体瓶颈、RL 利用的独特结构，并在相同质量目标和合理计算预算下证明收益。

### 论文边界

- 这是方法与系统趋势综述，不提供所有算法的完整推导、训练超参数或 reward 公式。
- 被引用工作跨越多个年份，不能视为完整的最新成果列表。
- 不同工作的优劣不是在同一公开 benchmark 上重新统一测量的排名。
- 许多学习式方案在 full-chip、不同 layer 和不同 process corner 上的稳健性仍需验证。
